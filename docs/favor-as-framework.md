## Decision in one line

**Interactive Favor App is the first full product on the Bootstrap English platform — and the boilerplate for launching other applications built the same way.**

---

## Why Electron is here

Electron is not an arbitrary desktop choice. **Bootstrap English** enforces certain client capabilities (native window, local runtime, device reach, offline-capable shell, embed paths). Electron meets those enforced capabilities. Capacitor is the mobile twin of the same web surface. Unity is the embedded spatial layer only.

---

## Unique servings (what this template offers)

| Serving | What it is |
|---------|------------|
| **Bootstrap English spine** | Intent-native language and capability contract the whole client stack must satisfy |
| **Personal favor ledger** | Verb favors (actions) and noun favors (provisions) as social-capital records |
| **YONAW + multi-axis reputation** | Community valuation without a single soul score |
| **Moment Matrix counsel** | Multi-axis utterance measurement — counsel only, never rank authority |
| **Instrument rack** | Mountable measurement instruments with explicit consumption contracts |
| **Bishop-born stewards** | Durable agents with explicit roles; being profile ≠ permission |
| **Dokan / WooCommerce marketplace** | Per-user storefronts for favor catalog and barter settlement |
| **Desktop + mobile + spatial** | Electron shell · Capacitor twin · Unity embed for map only |

These are the product capabilities other apps on the same platform can reuse as a template, not a claim that every serving is fully implemented runtime code today.

---

## Template use

1. Keep Bootstrap English as the capability contract.
2. Keep scores as counsel; policy authorizes; witnesses prove.
3. Reuse Electron / Capacitor / Unity layering only where the new product needs those enforced capabilities.
4. Do not invent a composite soul score or launder Matrix axes into rank or pay.
